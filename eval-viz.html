Pass rate by model, on the shared 15-task shortlist

Every model below was run against the same 15 (language, exercise) tasks, so this is the one apples-to-apples comparison in the dataset. A task with zero surviving runs (e.g. voided by a harness bug) silently drops out rather than counting as a fail. Models tied on pass rate are broken by average tries-to-pass — fewer tries ranks higher. The main model's other 210 tasks aren't included here — see its full-run figure in the stat row above.

Generation speed on passing runs

Completion tokens per second of wall-clock time, averaged over each model's passing shortlist runs. Duration and token counts both include every internal retry within a run, so this cancels out most of the "more tries = more work" effect — it's throughput, not luck.

Tokens generated per passing run

Tokens per pass, normalized to each exercise's own difficulty — 1.0× is the average token cost among models that passed that exercise, so a model that mostly solved cheap exercises isn't flattered and one that solved expensive ones (like clock, ~2.4× the shortlist average) isn't unfairly penalized. All three panels share one column order, so you can see whether a model's token cost, wall-clock cost, and retry cost all tell the same story. Each faint dot is one passing run; the bold dot per model is the average, connected to trace the trend. Tries taken is jittered slightly to keep identical values from stacking into one dot.

Exercise usefulness — is this task worth keeping?

Each of the 15 shortlist tasks with surviving data, plotted by cost (average wall-clock time, all models) against how much it splits the model field (0 = every model landed the same way, pass or fail; 1 = an even 50/50 split — the most information a task can give). A task voided entirely (e.g. by a harness bug) is left off rather than shown as a false 0/0. Bubble size is attempt count; color is which way the split leans. Cheap + high-split (top-left) is the best-value task; expensive + low-split (bottom-right) is the prime candidate to cut. The table's Quality column folds discriminative power, cost, and flakiness into one number (higher = better) — it's what orders the heatmap's rows above.

Pass vs. fail cost, per exercise

Every attempt at each shortlist exercise — passes in green, fails in red — showing how much work got burned whether or not it landed. The bold dots are the pass/fail averages; the dashed line is the gap between them. Tokens and duration share one column order (sorted by the token gap, biggest first) so the two panels compare directly — a mismatch between them (e.g. a big token gap but a small time gap) means passes and fails take a similar amount of wall-clock time despite very different token counts, often a sign of throttling or a slow non-generation step.
